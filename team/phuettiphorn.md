## Pragmatic Promise
ในรายวิชานี้ ผมสัญญาว่าจะเขียน Unit Test กำกับทุกครั้งก่อนสร้างฟังก์ชันใหม่ และจะเขียน Commit Message ให้ชัดเจนอธิบายเหตุผลของการเปลี่ยนโค้ด ไม่ใช่แค่บอกว่าแก้ไฟล์อะไร เพื่อให้เพื่อนในทีมเข้าใจ Context ได้ง่ายที่สุด

## ทำไมอยากเรียน SE
ผมอยากเรียน SE จะช่วยให้ผมวางระบบ สื่อสารกับทีม และจัดการวงจรการพัฒนาซอฟต์แวร์ (SDLC) ได้อย่างมีประสิทธิภาพมากขึ้น

## Broken Window ที่เคยเจอ
ในโปรเจกต์วิชาเรียนก่อนหน้านี้ ทีมของผมเคยเจอ Broken Window คือ **การละเลยไม่แก้ไข Warning ในโค้ดและไม่มีการจัด Format ให้เป็นมาตรฐานเดียวกัน** ตั้งแต่เริ่มโปรเจกต์ 

ผลกระทบคือเมื่อโค้ดสะสมมากขึ้น ความรกรุงรังนี้ทำให้สมาชิกคนอื่นเริ่มเขียนโค้ดแบบลวกๆ ตามกันไป (Bad Code Proliferation) จนในที่สุดโค้ดซับซ้อน อ่านยาก และเกิด Bug ที่หาจุดผิดพลาดได้ยากมากตอนใกล้ส่งงาน 

หากเราแก้ทันทีตั้งแต่แรกโดยการตั้งค่า Linter และ Auto-formatter พร้อมแก้ Warning ทันทีที่พบ จะช่วยป้องกันปัญหา Technical Debt ที่สะสม และทำให้ทีมรักษาสภาพแวดล้อมการทำงานที่มีคุณภาพสูงไว้ได้ตลอดการทำโปรเจกต์
