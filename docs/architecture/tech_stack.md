# ADR-001: การเลือกกลุ่มเทคโนโลยีหลัก (Selection of Core Technology Stack)

**สถานะ:** ยอมรับ (Accepted)

## บริบท (Context)
โปรเจกต์ของเรา **CampusLink** เป็นเว็บแอปพลิเคชันที่ออกแบบมาสำหรับนิสิตและบุคลากรของมหาวิทยาลัยพะเยา โดยมีฟีเจอร์หลักที่สำคัญ ได้แก่ ระบบการยืนยันตัวตนผ่านอีเมลของมหาวิทยาลัยโดยเฉพาะ, ระบบการสร้างและจัดการโพสต์เนื้อหา, และระบบการแจ้งเตือนความเคลื่อนไหวต่างๆ

ทีมของเราประกอบด้วยนิสิตที่มีประสบการณ์ในระบบนิเวศของ JavaScript/TypeScript สมัยใหม่ (React, Next.js, Tailwind CSS, Prisma และฐานข้อมูลเชิงสัมพันธ์) ข้อจำกัดหลักของเราคือระยะเวลาในการทำโปรเจกต์ที่มีจำกัด และความจำเป็นในการพัฒนาระบบต้นแบบอย่างรวดเร็วให้ครอบคลุมฟีเจอร์ที่กล่าวมา

## การตัดสินใจ (Decision)
เราได้ตัดสินใจเลือกใช้กลุ่มเทคโนโลยีหลักดังต่อไปนี้เพื่อรองรับความต้องการของระบบ:

* **Frontend & Backend Framework:** Next.js (เวอร์ชัน 15+)
* **Styling:** Tailwind CSS
* **Authentication (ระบบ Login):** NextAuth.js (Auth.js) หรือ Supabase Auth (ตั้งค่า OAuth ให้รับเฉพาะโดเมน `@up.ac.th`)
* **Database ORM:** Prisma
* **Database & Real-time:** PostgreSQL (โฮสต์บนแพลตฟอร์ม Supabase เพื่อใช้ฟีเจอร์ Real-time สำหรับระบบแจ้งเตือน)
* **Storage (ระบบเก็บไฟล์):** Supabase Storage (สำหรับการอัปโหลดรูปภาพหรือไฟล์แนบในโพสต์)
* **Deployment:** Vercel

## ผลลัพธ์ที่ตามมา (Consequences)

### ข้อดี (Positive)
* **การจัดการ Authentication ที่ปลอดภัย:** การใช้ NextAuth.js หรือ Supabase Auth ร่วมกับผู้ให้บริการ OAuth (เช่น Google Workspace) ทำให้เราสามารถจำกัดสิทธิ์การเข้าใช้งานได้เฉพาะผู้ที่มีอีเมลโดเมนของมหาวิทยาลัยได้อย่างรวดเร็ว โดยไม่ต้องพัฒนาระบบความปลอดภัยด้านรหัสผ่านเองทั้งหมด
* **โครงสร้างข้อมูลที่รองรับความซับซ้อน:** การใช้ Prisma ร่วมกับ PostgreSQL เอื้อต่อการออกแบบความสัมพันธ์ของข้อมูลที่เกี่ยวข้องกัน เช่น ผู้ใช้งาน 1 คน สามารถมีหลายโพสต์ และ 1 โพสต์สามารถเชื่อมโยงกับการแจ้งเตือนได้หลายรายการ
* **รองรับระบบแจ้งเตือนและไฟล์แนบ:** การใช้ Supabase ไม่ได้ตอบโจทย์แค่ฐานข้อมูล แต่ยังให้ระบบ Real-time subscriptions ที่สามารถนำมาประยุกต์ใช้กับระบบการแจ้งเตือนแบบทันทีทันใด (Push/In-app Notifications) และมี Blob Storage สำหรับจัดการไฟล์รูปภาพจากระบบสร้างโพสต์ได้ในที่เดียว
* **กระบวนการพัฒนาเป็นเนื้อเดียวกัน (Unified workflow):** ด้วย Next.js และนำขึ้นใช้งาน (Deploy) ผ่าน Vercel ได้อย่างรวดเร็ว

### ข้อควรระวัง / ข้อเสีย (Negative)
* **การตั้งค่า OAuth สำหรับอีเมลองค์กร:** อาจมีข้อจำกัดหรือต้องใช้เวลาในการตรวจสอบสิทธิ์จากทางผู้ให้บริการ (Google Cloud Console / Microsoft Entra) ในช่วงเริ่มต้นการพัฒนา
* **ข้อจำกัดของแพ็กเกจฟรี (Free Tier Limits):** ฟีเจอร์ Real-time สำหรับระบบแจ้งเตือน และการเก็บไฟล์ (Storage) สำหรับระบบโพสต์ หากมีการใช้งานพร้อมกันจำนวนมาก อาจทำให้ใช้ทรัพยากรเกินโควต้าของแพ็กเกจฟรีบน Supabase ได้ ทีมต้องออกแบบระบบให้มีการดึงข้อมูลหรือล้างข้อมูลเก่าอย่างมีประสิทธิภาพ
